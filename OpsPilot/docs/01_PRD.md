# Omni-Agent: 跨境电商全链路智能自动化专家 - 产品需求文档 (PRD)

## 1. 文档概览
- **项目名称**：Omni-Agent
- **版本**：V1.0 (工业级落地版)
- **目标用户**：跨境电商运营团队、采购部门、合规审计部门
- **核心价值**：通过多智能体协作与视觉增强技术，实现跨平台、跨系统的业务自动化，解决信息孤岛与合规风险。

## 2. 业务流程与逻辑设计

### 2.1 核心业务 SOP
系统需支持以下标准作业程序 (SOP)：
1. **需求接收**：解析用户自然语言指令（如：采购、比价、库存核查）。
2. **合规预审**：基于 RAG 检索最新的海关政策与平台规则。
3. **多方博弈**：采购 Agent 提出方案，财务 Agent 进行预算与合规审计。
4. **自动化执行**：
    - **API 路径**：通过 MCP 调用 GitHub/ERP 接口。
    - **GUI 路径**：若无 API，启动 UI-TARS 进行网页操作。
5. **结果归档**：生成审计日志并更新长期记忆。

### 2.2 状态机定义 (FSM)
| 状态 | 触发条件 | 动作 | 下一状态 |
| :--- | :--- | :--- | :--- |
| **INIT** | 用户输入指令 | 意图识别与任务拆解 | **PLANNING** |
| **PLANNING** | 任务拆解完成 | 检索 RAG 知识库，制定执行路径 | **AUDITING** |
| **AUDITING** | 路径制定完成 | 财务/合规 Agent 审核方案 | **EXECUTING** / **REJECTED** |
| **EXECUTING** | 审核通过 | 调用 MCP 工具或 GUI 动作 | **VERIFYING** |
| **VERIFYING** | 执行动作完成 | 检查执行结果是否符合预期 | **SUCCESS** / **RETRY** |

## 3. 功能需求说明

### 3.1 多智能体协作模块 (AgentScope)
- **Orchestrator Agent**：负责全局状态管理与任务分发。
- **Buyer Agent**：负责供应商筛选、价格谈判逻辑模拟。
- **Compliance Agent**：负责合规性校验，具备 RAG 检索权限。
- **Executor Agent**：负责底层工具调用的封装与异常捕获。

### 3.2 增强型执行模块 (LangChain + MCP + GUI)
- **MCP 集成**：必须支持标准 JSON-RPC 通信，实现工具的动态注册。
- **GUI 自动化**：UI-TARS 需支持 `click(x, y)`, `type(text)`, `scroll()` 等原子动作，且具备视觉反馈验证。
- **RAG 管道**：支持 PDF/Markdown 格式解析，采用 BGE-Reranker 进行二次精排。

### 3.3 模型优化模块 (LLaMA-Factory + SGLang)
- **微调约束**：模型需在微调后能够 100% 识别自定义的 `Action: [Tool Name]` 语法。
- **推理约束**：SGLang 需开启 `json_mode`，确保输出参数严格符合 Pydantic 定义的 Schema。

## 4. 非功能性需求 (NFR)

### 4.1 性能指标
- **首字延迟 (TTFT)**：在 SGLang 优化下，复杂任务的首字延迟应控制在 1.5s 以内。
- **任务成功率**：在标准 Mock 环境下，端到端 SOP 成功率需达到 90% 以上。

### 4.2 用户准入与分级体系 (Role-Based Action Control)

#### 4.2.1 角色权限矩阵
| 角色 | 采购金额上限 | 敏感操作权限 | 审批权限 | 数据访问范围 |
| :--- | :--- | :--- | :--- | :--- |
| **初级采购员** | ≤ 10 万元 | 无 | 无 | 仅本人发起的订单 |
| **高级采购员** | ≤ 50 万元 | 供应商信息查看 | 无 | 本部门订单 |
| **财务审核员** | - | 合同审计、预算查询 | ≤ 100 万元订单审批 | 财务相关数据 |
| **系统管理员** | 无限制 | 全部 | 全部 | 全部数据 |

#### 4.2.2 Agent 执行策略约束
- **金额触发审批**：当采购订单金额超过角色上限时，Agent 自动冻结流程并通知上级审批。
- **敏感操作二次确认**：涉及支付、合同签署的操作，必须触发 `Human-in-the-loop` 人工确认。
- **权限边界校验**：每次工具调用前，系统校验当前角色的 `Action Permit List`，拒绝越权操作。

#### 4.2.3 权限升级流程
```
[初级采购员] --发起超额订单--> [Agent 自动锁定] --> [通知财务审核员] --> [审批通过] --> [执行]
```

### 4.3 异常场景处理机制

#### 4.3.1 RAG 检索失败降级策略
| 场景 | 默认策略 | 处理方式 |
| :--- | :--- | :--- |
| 政策库无匹配结果 | 保守策略 | 拒绝操作并提示人工介入，不进行推测性决策 |
| 政策冲突（新旧政策） | 时效优先 | 优先采用最新发布日期的政策，并标注政策版本 |
| 政策解读模糊 | 多 Agent 投票 | 启动合规 Agent 与法务 Agent 博弈，需 2/3 多数通过 |

#### 4.3.2 MCP 工具不可用降级路径
```
[API 调用失败] --> [指数退避重试 3 次] --> [降级至 GUI 模式] --> [UI-TARS 视觉执行] --> [人工确认结果]
```

#### 4.3.3 多 Agent 博弈仲裁机制
- **超时仲裁**：当博弈超过 5 轮仍未达成一致，触发 `Orchestrator Agent` 强制仲裁。
- **权重投票**：不同 Agent 根据专业领域设置投票权重（如合规 Agent 在法规问题上有 1.5x 权重）。
- **人工介入阈值**：当分歧值超过 0.7（归一化），强制引入人工决策。

### 4.4 合规性设计 (Compliance)

#### 4.4.1 数据保护法规适配
- **GDPR 合规**：
  - 支持用户数据删除请求（Right to be Forgotten）
  - 个人数据加密存储，访问日志保留 7 年
  - 数据跨境传输采用 TLS 1.3 + 国密 SM4 双重加密
- **数据本地化**：欧盟用户数据存储于法兰克福节点，中国用户数据存储于上海节点

#### 4.4.2 审计日志设计
| 日志类型 | 保留期限 | 存储方式 | 防篡改机制 |
| :--- | :--- | :--- | :--- |
| 操作轨迹 | 7 年 | 冷存储 (OSS) | 哈希链 + 时间戳签名 |
| 决策日志 | 7 年 | 数据库 + 备份 | Merkle Tree 校验 |
| 敏感数据访问 | 10 年 | 专用审计库 | WORM (Write Once Read Many) 存储 |

#### 4.4.3 合规报告生成
- 自动生成月度合规审计报告，包含：操作成功率、异常处理统计、权限使用情况
- 支持导出符合 SOX、ISO 27001 标准的审计文档

### 4.5 安全与合规
- **操作审计**：所有 GUI 动作必须录制截图序列，存入 `logs/trajectories`。
- **权限控制**：敏感操作（如支付）必须通过 `Human-in-the-loop` 接口获取人工授权。

## 6. 验收标准
1. **场景跑通**：能够完整演示“从需求输入到 ERP 自动录入”的闭环。
2. **方法论体现**：文档中必须清晰展示如何将此流程迁移至其他垂直行业。
3. **工程化完备**：具备完善的日志、评估脚本和微调数据采集工具。
